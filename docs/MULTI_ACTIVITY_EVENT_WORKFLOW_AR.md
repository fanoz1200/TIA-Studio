# ربط واقعة واحدة بعدة أنشطة متأثرة

## الهدف

يسمح مسار **Activity split** بإنشاء واقعة TIA واحدة وربطها بعدد غير محدود من الأنشطة المتأثرة داخل نسخة **Post‑TIA** فقط. يساعد البحث المحلي والـcheckboxes المحلل في انتقاء الأنشطة بالـID أو الاسم أو WBS، كما تُنقل كل `affectedActivityIds` الموجودة في Issue Log Excel إلى الاختيار عند تطبيق سجل الواقعة.

لا تُرفع أسماء الأنشطة أو ملفات XER أو بيانات Excel إلى خدمة خارجية بسبب هذا الاختيار؛ المعالجة تظل محلية داخل جلسة البرنامج.

## ما ينشئه البرنامج

لكل نشاط مختار ينشئ البرنامج سلسلة منفصلة داخل الـFragnet المركب:

```text
Original activity  →  Pre  →  Event  →  Post
```

تظل الأنشطة الأصلية كما هي في نسخة Pre‑TIA. في Post‑TIA فقط تُستبدل الأنشطة المختارة بسلاسلها، وتحمل الواقعة مصفوفتي `sourceActivityIds` و`replacedActivityIds` لإتاحة التتبع ومراجعة نطاق الموارد المرتبط بالواقعة.

| الشرط | سلوك التطبيق |
|---|---|
| النشاط غير موجود | يوقف الإنشاء برسالة تحقق واضحة. |
| تاريخ الواقعة خارج مدة أي نشاط مختار | يوقف الإنشاء؛ يجب أن يقع التاريخ داخل كل نشاط. |
| علاقة نشاط مختار من نوع غير FS أو بها Lag | يوقف التقسيم الآلي لهذا النشاط. |
| نشاطان مختاران بينهما علاقة مباشرة | يرفض التقسيم المجمع؛ ينشئ المحلل واقعتين أو Fragnet يدوياً بعد مراجعة المنطق. |
| تعدد events | يبقى مدعوماً؛ كل واقعة لها Fragnet ومعرفات مصدر مستقلة. |

> الرفض في حالة الأنشطة المرتبطة مباشرة مقصود. إعادة توصيل عدة splits متداخلة تلقائياً قد تغيّر منطق الشبكة، لذلك لا ينتج التطبيق علاقة افتراضية أو نتيجة أثر زمني غير قابلة للتدقيق.

## حدود المراجعة المهنية

هذه الميزة لا تعني محاكاة Primavera P6 أو F9، ولا تحل محل مراجعة التقويمات المتعددة والـActuals والـRemaining Duration والـData Date والـresource leveling والـretained logic داخل بيئة الجدولة المعتمدة. كما أن الأثر المحسوب لا يقرر وحده الاستحقاق التعاقدي أو EOT أو توزيع المسؤولية.

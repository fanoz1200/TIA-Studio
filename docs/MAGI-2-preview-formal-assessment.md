# التقييم الرسمي لمستودع MAGI-2 Preview لإنتاج فيديوهات تدريب TIA

**تاريخ التقييم:** 19 أغسطس 2026  
**نطاق القرار:** تقييم MAGI-2 Preview من Sand AI بوصفه أداة إنتاج خارجية ومحدودة لفيديوَي التدريب القصيرين: **رفع برنامج P6** و**إدخال نموذج Excel**. لا يتعلق هذا التقييم بتشغيل محرك تحليل التأخير، الذي يبقى محلياً داخل المتصفح ولا يعتمد على نموذج ذكاء اصطناعي.

> **الخلاصة التنفيذية:** المستودع قابل للمتابعة كخيار إنتاج احترافي على بنية GPU منفصلة ومؤهلة، لكنه **غير قابل للتشغيل أو الإنتاج في بيئة المشروع الحالية**. لذلك لا يُدمج في خادم التطبيق، ولا يوجد فيديو مولّد منه في هذا الإصدار. جُهزت سيناريوهات الإنتاج وصور مرجعية آمنة، ويبدأ التوليد الفعلي فقط بعد توفير بيئة GPU مطابقة واجتياز اختبار صوت عربي.

## 3. فحص قابلية البيئة الحالية

تم إجراء فحص غير تدخلي للبيئة قبل تنزيل أي أوزان أو تشغيل أي كود من المستودع. النتيجة محفوظة كذلك في `docs/magi-2-local-environment-check.txt`.

| مورد أساسي | المتاح في البيئة الحالية | مقارنة بالمطلوب | القرار |
| --- | --- | --- | --- |
| NVIDIA GPU | لا يوجد؛ الأمر `nvidia-smi` غير متاح. | الوثائق تشير إلى ثماني وحدات Hopper. | **مانع قاطع للتشغيل**. |
| CUDA | لا يوجد؛ الأمر `nvcc` غير متاح. | CUDA حديث مطلوب لمسار التشغيل. | **مانع قاطع للتشغيل**. |
| مساحة التخزين الحرة | 37 GB تقريباً. | الأوزان وحدها تقارب 307 GB، قبل التبعيات والمخازن المؤقتة. | **مانع قاطع للتنزيل**. |
| ذاكرة النظام المتاحة | 20 GiB تقريباً. | لا تعوض غياب GPU ولا حجم النموذج. | غير كافية كبديل عملي. |
| Docker | غير متاح. | الصورة الرسمية تتوقع بيئة NVIDIA Docker مناسبة. | مانع إضافي لمسار الحاوية الرسمي. |

> لا يعد تثبيت الحزم أو استنساخ المستودع أو تنزيل أوزان 307 GB محاولة إنتاج حقيقية ما دامت هذه الموانع قائمة؛ بل يستهلك موارد دون مسار نجاح معقول. لذلك **لم يُنزّل النموذج ولم يُشغّل كود غير موثوق** في بيئة التطبيق.

## 4. قرار الاستخدام والدمج الآمن

### القرار

**لا يُدمج MAGI-2 داخل التطبيق ولا في خادم النشر الحالي.** يوصى به فقط كمسار إنتاج تحريرّي منفصل عند توفر عامل GPU مؤقت أو حاسوب مخصص يطابق المتطلبات، وليس كميزة وقت تشغيل للمستخدمين.

هذا القرار يحافظ على متطلبات المنصة: تحليل TIA وقراءة ملفات P6 ومعالجة Excel تظل محلية في المتصفح، ولا تُرسل بيانات المستخدم إلى MAGI-2 أو إلى أي نموذج خارجي.

### البنية الآمنة المقترحة عند توفر GPU

1. إنشاء بيئة GPU منفصلة، قصيرة العمر، بلا اتصال بقاعدة بيانات التطبيق أو مساحة ملفات المستخدمين.
2. تثبيت إصدار المستودع عند **التزام Git محدد** ومراجعة Dockerfile الرسمي، مع إنشاء SBOM وفحص الثغرات قبل التنفيذ.
3. تشغيل النموذج داخل حاوية معزولة، مع تعطيل `prompt_enhancement` وأي نقطة نهاية خارجية.
4. استخدام فقط النصوص العربية والصور التجريبية النظيفة التي أعدت لهذا الفيديو؛ يمنع رفع XER أو XML أو Excel حقيقي أو Evidence أو Notice أو بيانات مطالبة.
5. تشغيل اختبار قبول من ثلاث لقطات: وضوح العربية، سلامة التزامن، وعدم نطق أسماء الملفات أو المصطلحات الخاطئة بصورة مضللة.
6. فحص الفيديو يدوياً من مسؤول المشروع، ثم حفظ MP4 النهائي في الأصول الدائمة خارج المستودع وربطه بالمكتبة دون تضمين النموذج أو أوزانه في عملية النشر.

## 5. ما تم إنجازه فعلياً للإنتاج

أُعدت حزمة الإنتاج التفصيلية في `docs/magi-2-training-production-packet.md`، وتتضمن النص الصوتي، اللقطات، موجهات التوليد، قواعد قبول العربية، وسياسة الخصوصية لكل من الفيديوين. كما تم التحقق بصرياً من مسار Workshop 8 في واجهة التطبيق باستخدام مشروع الاختبار فقط، وحُفظت لقطة مرجعية نظيفة لبوابة رفع Baseline في:

```text
/home/ubuntu/webdev-static-assets/magi2-training-references/p6-baseline-upload-reference.webp
```

لا تحتوي اللقطة ملفاً مرفوعاً ولا بيانات مشروع حقيقية. وهي أصل تحضيري داخلي، وليست فيديو منشوراً ولا يحق وصفها بأنها مخرَج MAGI-2.

## 7. توصية نهائية

يُصنّف MAGI-2 Preview **"مناسباً مشروطاً للإنتاج الخارجي المنفصل، وغير مناسب للتشغيل في البنية الحالية"**. لا أنصح بربطه مباشرة بالتطبيق أو باستعماله لتوليد محتوى مرتبط بملفات المستخدم. أفضل خطوة تالية هي تجهيز عامل GPU مؤقت مطابق لمتطلبات Sand AI، ثم تنفيذ اختبار قبول قصير باللغة العربية قبل إنتاج الفيديوين ورفعهما كمحتوى ثابت. إلى ذلك الحين، يبقى الإرشاد النصي التفاعلي الموجود في المكتبة هو مادة التدريب المنشورة الصحيحة والشفافة.

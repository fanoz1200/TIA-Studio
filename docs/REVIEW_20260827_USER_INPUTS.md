# سجل مراجعة مدخلات المستخدم — 27 أغسطس 2026

> **حالة السجل:** نقاط مراجعة واردة من ملفات المستخدم، وليست مواصفات معتمدة أو حقائق مُثبتة تلقائياً. لا يحتوي هذا السجل على ملفات XER أو Excel أو دليل مطالبة أو بيانات مشروع خام.

## تقرير دمج المنهجية

التقرير المرفق يقترح ترتيب تحسينات TIA Studio على ثلاث طبقات: أولاً تصحيح أساسيات الحساب والتقويم والقيود قبل التوسع المنهجي؛ ثانياً تطوير نوافذ التحديثات والتزامن وDCMA وطرق تحليل إضافية؛ وثالثاً إعادة هيكلة مخرجات التقرير والمطالبة. كما يصنف طرق تحليل التأخير وفق أربعة أبعاد: استشرافي/رجعي، نمذجي/رصدي، ديناميكي/ساكن، ومتدرج/إجمالي.

**الاستجابة الحالية:** تم خلال الدورة الحالية حماية بايتات XER، والفحص المحافظ لمعطيات التقويم، وفصل TIA عن Time Slice وHalf–Zero، وبروتوكول Reverse Import/Schedule-F9. ما زالت قراءة التقويم الحسابية الكاملة، حساب P6 المطابق، والتحقق داخل Primavera P6 غير مكتملة ولا تُدّعى.

## حدود الخصوصية والأمان

لا تُضاف ملفات ورشة المستخدم، أو XER المثال، أو Excel، أو أدلة، أو مطالبات إلى Git أو أمثلة المشروع. سيُستخلص فقط وصف تقني عام ومجهّل عند الحاجة إلى اختبار محلي، بعد فحص قائمة محتويات الأرشيف قبل الاستخراج.

## Workshop No.9 — Time Slice / Windows Analysis

> **حدود المراجعة:** فُك الأرشيف محلياً في مساحة فحص خارج المشروع. لا تُنسخ الملفات المستخرجة أو محتواها الخام إلى المستودع أو قاعدة البيانات أو التخزين أو أمثلة التطبيق.

الأرشيف يحتوي على ملف XER واحد، وملف Excel واحد، وثلاثة نماذج Event Record بصيغة DOCX وثلاث نسخ PDF مقابلة؛ لم يحتوِ ملفات تنفيذية. بنية ملف Excel التعليمية تتضمن برنامج أساس، وثلاث نوافذ متتابعة، وجدول تحليل للتأخير، وصفيحتي مقارنة فروق. تعرض جداول النوافذ—على مستوى العناوين فقط—معرف/اسم النشاط، المدة الأصلية، Start/Finish، نسبة الإنجاز المادي، مدة الإكمال، Actual Start/Finish، وData Date.

نماذج الوقائع التعليمية تؤكد تسلسل العمل الآتي: تثبيت الواقعة وتاريخ المخطط/الواقع أو مدتها، ربطها بالأدلة والإشعار المؤرخ والمستلم، ثم توثيق حالة التزامن عندما توجد واقعة لصاحب العمل وأخرى للمقاول. هذه **متوافقة جزئياً** مع TIA Studio: Time Slice الحالي رصدي بين تحديثين ويعرض فروق الأنشطة وData Date؛ كما توجد سجلات وقائع وأدلة وتحذير مهني من تحويل التزامن إلى قرار تلقائي. ما زالت نقاط تحقق Primavera P6 الفعلية، وفك التقويم كاملاً، وإثبات سبب/استحقاق أو توزيع مسؤولية خارج نطاق الحساب المحلي وتبقى للمراجع المختص.

| نتيجة مراجعة الورشة | وضعها في TIA Studio | الإجراء الآمن |
|---|---|---|
| Baseline ثم نوافذ تحديث متتابعة | مدعوم كمدخلات منفصلة للمراجعة | يبقى المستخدم مسؤولاً عن اختيار النافذة وData Date الصحيحين |
| مقارنة تغير نشاط بين نافذتين | محسوبة رصدياً في Time Slice | لا تُفسر كسبب أو مسؤولية تلقائياً |
| نسب الإنجاز وActual Start/Finish | تُقرأ كبيانات تقدم وتدخل في بوابة الجاهزية | لا تُسوّى أو تُعاد كتابتها تلقائياً |
| سجل Event Record وNotice مستلم | مدعوم كمسار دليل/Notice محلي | يحتاج تأكيد المستندات والعقد من المراجع |
| Concurrent delay | يسجل كحالة مراجعة وإفصاح | لا يوجد تقسيم entitlement أو EOT آلي |

## نتيجة تدقيق قابلية إعادة البناء وPDF

تمت معالجة **اعتمادية الاختبارات** التي كانت تقرأ خطاً من مسار محلي خارج المستودع؛ لذلك لم تعد اختبارات المصدر النظيف تحتاج ملفاً من مساحة أصول البيئة. تؤكد الاختبارات الآن المسار الآمن التالي: PDF إنجليزي يُنشأ من دون fetch للخط العربي، وPDF عربي يتوقف برسالة محددة إذا لم يُحمّل الخط بدلاً من إخراج ملف مشوّه. لا يحل ذلك محل فحص مرئي يدوي لـPDF عربي داخل جلسة التطبيق التي تسمح بالوصول إلى أصل الخط المنشور، ولا يغير محتوى التقرير أو أحكامه المهنية.

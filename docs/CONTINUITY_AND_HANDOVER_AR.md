# استمرارية TIA Studio وتسليم المصدر

## الهدف

الهدف أن يظل **كود TIA Studio** ونسخة البناء وتعليمات التشغيل قابلة للاستلام من مطور أو وكيل جديد حتى إذا تغيرت منصة عمل أو نموذج ذكاء اصطناعي أو خدمة استضافة. لا يعني ذلك نقل بيانات العملاء أو تشغيل نظام نسخ احتياطي سحابي تلقائي؛ هذا الدليل ينشئ مسار تسليم يدوي واضح للمالك.

> **مصدر الحقيقة:** GitHub المنظم، ونسخة مصدر يدوية من commit محدد، ووثائق التشغيل داخل المستودع. لا تكون أي محادثة أو منصة أو نموذج ذكاء اصطناعي هو المصدر الوحيد للمشروع.

## ما يدخل في حزمة الاستلام

| العنصر | يدخل؟ | السبب |
|---|---:|---|
| مصدر Git المتعقب عند commit نظيف | نعم | يمكن البناء والمراجعة واستكمال التطوير منه. |
| `pnpm-lock.yaml` وأوامر البناء والاختبارات | نعم | تثبيت الاعتمادات القابلة للتكرار. |
| دليل Windows وملاحظات الإصدار والقرار الفني | نعم | شرح الحزم والحدود وسبب إصلاح Vite. |
| ملفات `.env` والمفاتيح والجلسات | لا | أسرار تشغيل خاصة بالبيئة ولا تصلح للتبادل. |
| XER/XML/XLSX الخام وأدلة العميل والمراسلات | لا | بيانات مشروع حساسة تبقى عند المالك في تخزين منفصل ومصرح. |
| `node_modules` و`dist` و`release` | لا | مخرجات كبيرة قابلة لإعادة البناء أو التحميل من روابط الإصدار المعتمدة. |

## إنشاء الحزمة يدوياً

بعد نجاح الاختبارات وحفظ نقطة العمل، افتح مجلد المشروع على جهاز التطوير وشغّل:

```bash
pnpm continuity:package --output /مسار/خارج/المشروع/TIA-Studio-Handover
```

إذا لم تحدد `--output`، ينشئ الأمر مجلداً مجاوراً للمشروع باسم `TIA-Studio-Handover`. يرفض الأمر العمل إذا كانت شجرة Git تحتوي تغييرات أو ملفات غير متعقبة؛ هذه حماية حتى لا تُنسب نسخة غير مكتملة أو ملف عميل غير مقصود إلى حزمة التسليم.

ينتج الأمر مجلداً مثل `TIA-Studio-Handover/TIA-Studio-Handover-<commit>` يحتوي على الآتي:

| الملف | استخدامه |
|---|---|
| `README_FIRST_AR.md` | نقطة البدء السريعة وروابط حزم Windows الحالية وبصماتها. |
| `handover-manifest.json` | commit المصدر، بصمة الأرشيف، وقائمة الاستثناءات المتعمدة. |
| `TIA-Studio-source-<commit>.tar.gz` | أرشيف مصدر من الملفات المتعقبة فقط. |

احفظ هذا المجلد في **مكانين يسيطر عليهما المالك**، مثل قرص خارجي مشفّر وتخزين خاص. هذا قرار تشغيلي يدوي وليس خدمة نسخ احتياطي؛ لا تنشئ نسخاً احتياطية تلقائية ولا ترفع بيانات العميل إلى مستودع عام أو إلى خدمات ذكاء اصطناعي.

## استلام المشروع من مطور أو وكيل جديد

يفك المستلم أرشيف المصدر ثم ينفذ الأوامر التالية:

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm check
pnpm build
```

لإنتاج حزمة Windows جديدة، يجب بعد ذلك استخدام `pnpm desktop:pack:windows` ثم تجربة Portable أولاً واتباع فحص Windows الفعلي الموثق في `docs/TIA_STUDIO_DESKTOP_RELEASE_AR.md`. لا يكفي بناء ملف EXE دون اختبار إقلاع وتثبيت واضح.

تظل الحسابات الأساسية CPM/TIA محلية وحتمية. أما تسجيل الدخول ودعوات الأعضاء والسجل المشترك والتخزين السحابي فتحتاج بيئة خدمة مكافئة وإعداد أسرار جديداً؛ لا تُنسخ مفاتيح البيئة أو جلسات المستخدم ضمن حزمة الاستلام.

## قواعد العمل مع أي وكيل خارجي

يجب أن يعمل أي وكيل أو مطور في فرع مستقل وPull Request، مع قراءة `CONTRIBUTING.md` وتشغيل بوابة الإصدار. لا يسمح له بالعمل على `main` مباشرة، أو حذف تاريخ Git، أو رفع ملفات العميل الخام. يقتصر ما يرسل إلى خدمة ذكاء اصطناعي خارجية على وصف مجهّل أو Fact Pack منظّم بعد موافقة المالك، وليس ملفات XER/XLSX الأصلية أو المراسلات أو الأدلة.

يوصى أن يجعل المالك مستودع GitHub **خاصاً** إذا كان يتضمن سياقاً غير مخصص للنشر، وأن يفعّل حماية `main` لمنع الـforce-push وحذف الفرع والدمج دون مراجعة. لا يغني ذلك عن الاحتفاظ بحزمة الاستلام اليدوية الدورية في مكان مستقل.

## القرار الخاص بالميزات التالية

| المسار | الحالة الآن | الخطوة الصحيحة التالية |
|---|---|---|
| إصلاح تشغيل Windows | مكتمل في الكود وPortable، وSetup بُني | اختبار Setup على جهاز Windows فعلي قبل الاعتماد النهائي. |
| استمرار المصدر | حزمة يدوية موثقة | تنفيذها يدوياً بعد كل إصدار كبير أو قبل تغيير منصة/فريق. |
| صلاحية فريق مؤقتة | غير منفذة | تنفيذ `accessExpiresAt` وفحص خادمي مركزي بعد اعتماد نطاق فريق الويب. |
| Full Claim / Narrative DOCX | غير منفذ كقالب ثابت جديد | يبدأ بـFact Pack منظم وقالب DOCX، لا بـprompt ضخم أو بيانات ناقصة. |

## الحدود المهنية

حزمة الاستلام لا تثبت تكافؤ Primavera P6، ولا تثبت استحقاقاً قانونياً أو مالياً. يجب اختبار أي XER مصدر على نسخة P6 غير إنتاجية، ومراجعة التقويم والعلاقات والمسار الحرج، ومراجعة أي مطالبة من مختص بالعقود أو القانون قبل اعتمادها.

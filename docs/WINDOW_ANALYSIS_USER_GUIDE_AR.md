# دليل Window Analysis / Time Slice في TIA Studio

> **الغرض:** هذا المسار يساعد فريق التخطيط في قراءة تغيّر البرنامج بين نسخ متتابعة محفوظة محلياً. إنه **لا** يمنح تلقائياً تمديد وقت، أو مقابلاً مالياً، أو نسبة مسؤولية، ولا يحل محل مراجعة العقد والسجلات والتخطيط.

## ما هي Window Analysis ببساطة؟

تخيّل المشروع مثل فيلم مقسم إلى مشاهد زمنية. كل **Window** هي فترة بين نسخة برنامج وأخرى: مثلاً برنامج الأساس، ثم Update يناير، ثم Update فبراير. بدل أن نضيف Fragnet افتراضي إلى برنامج واحد، نقارن ما كان معروفاً عند بداية كل فترة بما ظهر في النسخة التالية، ثم نقرأ فرق تاريخ الإنجاز وتغير الأنشطة والسياق الواقعي للواقعة والأدلة.

| المصطلح | معناه داخل البرنامج | ما يجب على المحلل مراجعته |
|---|---|---|
| Baseline | الخطة المعتمدة أو نسخة البداية المختارة | تاريخ البدء/الإنهاء، Data Date، التقويم، القيود، ومنطق العلاقات. |
| Update snapshot | نسخة P6/XER/XML أو Snapshot محملة بعد ذلك | هل النسخة صحيحة ومرتبة زمنيًا؟ وهل Data Date معروف؟ |
| Window / Time Slice | المقارنة بين نسختين متتاليتين | تغير تاريخ الإنجاز، المدة، الإضافة أو الحذف، التقويم والتحذيرات. |
| سجل الوقائع | سبب وتأريخ الحدث كما سجله المستخدم | ربط الواقعة بالأدلة والأنشطة، لا افتراض السببية من فرق الجدول وحده. |
| تحليل TIA | محاكاة Fragnet على برنامج مختار | مسار منفصل عن Time Slice ولا ينبغي وصف Time Slice بأنه TIA. |

## ما الذي ينفذه TIA Studio حالياً؟

يوفر التطبيق مسارين منفصلين حتى لا تختلط المصطلحات:

| المسار | المدخلات | النتيجة الفعلية | ليس نتيجة له |
|---|---|---|---|
| **Windowed TIA** | برنامج مختار وFragnet وواقعة | تحليل CPM/Fragnet ضمن نافذة تشغيلية | Window Analysis رصدي بين تحديثات تاريخية. |
| **Time Slice Window Analysis** | Baseline وUpdate واحد أو أكثر محمّلة محلياً | مقارنة رصدية لنسختين متتاليتين: فرق الإنجاز، فرق المدة، تغير الأنشطة وتحذيرات جودة | دليل سببية أو قرار EOT/تعويض أو إرسال Claim. |

محرك **Time Slice** يرتب اللقطات باستخدام `dataDate`، ويرفض ترتيباً زمنياً غير صحيح، ويعيد حساب CPM محلياً لكل لقطة، ويقارن توقيع التقويم، ويظهر فرق تاريخ الإنجاز بوحدات التقويم وأيام العمل، ثم يسجل الأنشطة المضافة أو المحذوفة أو التي تغيرت مدتها. لا يعدل ملف المصدر ولا يرفع أي ملف P6/XER/XML/XLSX أو دليل إلى خدمة خارجية.

## طريقة الاستخدام العملية

1. ارفع **Baseline** ثم كل **Update** متاح من داخل رحلة التحليل. حافظ على اسم كل ملف وData Date كما وردا؛ لا تغيّر المصدر لأجل العرض.
2. افتح شاشة **Windows / النوافذ** ثم قسم **Time Slice Window Analysis**.
3. اختر النسخة الأسبق والنسخة اللاحقة. لا تقارن نسخاً غير مرتبة زمنياً.
4. راجع تاريخ الإنجاز والفرق الزمني وسجل تغير الأنشطة، ثم اقرأ تحذيرات Data Date والتقويم والجودة.
5. افتح سجل الوقائع والأدلة. اربط كل واقعة بالأدلة والأنشطة ونطاق النافذة بعد مراجعة المحلل؛ لا تعتبر التغير الظاهر سبباً تلقائياً.
6. إذا احتجت محاكاة Fragnet، استخدم مسار **TIA** المنفصل وحدد فرضياته. لا تستبدل Time Slice هذه المحاكاة ولا العكس.
7. عند تجهيز Claim/EOT، نزّل قالب Claim/EOT المحلي من سجل Notices. القالب يضع نتيجة Time Slice أو TIA كمدخلة فنية قابلة للمراجعة، ولا يحولها إلى استحقاق تلقائي.

## فحوص لا يجوز تجاوزها

| فحص | لماذا هو مهم؟ | الإجراء الصحيح |
|---|---|---|
| تسلسل Data Dates | المقارنة المعكوسة تخلق نتيجة مضللة | استخدم نسخة أسبق ثم نسخة لاحقة، وصحح التاريخ قبل التحليل. |
| التقاويم | فرق تقويم العمل قد يغير تفسير الأيام | راجع فرق التقويم وأظهره صراحة في السرد. |
| منطق وقيود البرنامج | تغير القيود أو العلاقات قد يحرك تاريخ الإنجاز بلا واقعة معزولة | شغّل بوابة جودة البرنامج وافحص المنطق والقيود. |
| اكتمال التحديث | النسخة غير المعتمدة أو الناقصة ليست دليلاً كافياً | احتفظ بمصدر النسخة ومالكها وتاريخها وملاحظات الاستلام. |
| السببية والمسؤولية | فرق CPM لا يثبت من تسبب في التأخير | اربط الواقعة والسبب والسجل والأدلة والعقد بمراجعة بشرية. |

## علاقة النتيجة بالقوالب

القوالب المستخلصة من نماذج المستخدم تنظم الغلاف والواقعة والتسلسل والتحليل الفني والتكلفة والأدلة والموقف المطلوب وقائمة المراجعة. لكن **التحليل الفني** و**الموقف التعاقدي** قسمان منفصلان عمداً. قبل إصدار أي Notice أو Claim أو EOT، يجب مراجعة التواريخ والبند والنص والأدلة ونسخ البرنامج مع الفريق المفوض والعقد الحاكم.

## مراجع للتعلّم

توجد المراجع المهنية وروابطها وحدود استخدامها في [سجل البحث](./WINDOW_ANALYSIS_METHOD_RESEARCH_AR.md). تستخدم للتعلّم والمنهج الفني، وليست بديلاً عن العقد أو المشورة القانونية الخاصة بالمشروع.

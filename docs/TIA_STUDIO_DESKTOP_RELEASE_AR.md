# دليل إصدار وتشغيل سطح المكتب — TIA Studio

## الغرض الحقيقي من نسخة سطح المكتب

هذه النسخة تغلف منصة **TIA Studio** داخل تطبيق سطح مكتب Electron. يبدأ التطبيق خادماً محلياً على العنوان `127.0.0.1` فقط، ثم يفتح الواجهة في نافذة مستقلة. لا يفتح المنفذ على الشبكة المحلية، ولا يمنح واجهة المستخدم صلاحية مباشرة لتنفيذ أوامر نظام التشغيل.

> **حدود صريحة:** يعمل استيراد ملفات XER/XML، الحساب المحلي لـ CPM/TIA، بوابة جودة الجدول، المشاريع التدريبية، وتصدير Word/PDF/Excel داخل النسخة المحلية. أما تسجيل الدخول، الدعوات، قاعدة البيانات المشتركة، التخزين السحابي، والإشعارات فتحتاج خدمة المنصة وبيانات اعتماد صحيحة، ولذلك لا تُعتمد أثناء العمل دون اتصال.

## تشغيل المستخدم على الكمبيوتر الشخصي

لا يحتاج المستخدم إلى تثبيت Node.js أو pnpm أو فتح موجه أوامر. يحمّل ملفاً واحداً مناسباً لنظامه ثم يفتحه بنقرتين:

| نظام التشغيل | الملف الذي يحمّله المستخدم | طريقة التشغيل |
|---|---|---|
| Windows x64 | `TIA-Studio-<الإصدار>-Windows-x64.exe` | افتح الملف مباشرة. الحزمة **Portable** وتفك محتويات التشغيل المطلوبة تلقائياً ثم تفتح نافذة TIA Studio. |
| Linux x64 | `TIA-Studio-<الإصدار>-Linux-x64.AppImage` | اجعل الملف قابلاً للتشغيل مرة واحدة ثم افتحه بالنقر المزدوج. |

> **تنبيه حماية صريح:** الحزم الحالية غير موقعة رقمياً. لا تعطل الحماية بشكل عام ولا تستخدم رابطاً مجهولاً. حمّل الملف من مركز الموارد الخاص بالإصدار، وافحصه ببرنامج الحماية في جهازك قبل أول تشغيل. تظهر نافذة TIA Studio فقط بعد أن يبدأ خادم محلي مقيد بعنوان `127.0.0.1`؛ لا يتاح لأي جهاز آخر على الشبكة.

عند فتح الملف ينشئ التطبيق ما يحتاجه مؤقتاً ويشغّل خادمه الداخلي، ثم يفتح النافذة تلقائياً. عند إغلاق النافذة يتوقف الخادم الداخلي. لا توجد أوامر يكتبها المستخدم ولا توجد خدمة دائمة تعمل في الخلفية.

## الإنشاء على جهاز تطوير

يتطلب الإنشاء Node.js 22 أو أحدث وpnpm. من جذر المشروع نفّذ:

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm desktop:release
```

ينتج الأمر الأخير ملفين منفصلين في مجلد `release/`: ملف EXE محمول واحد لـ Windows وملف AppImage واحد لـ Linux. في بيئة Linux المجهزة بـ Wine وXvfb، نفّذ أيضاً الأمر الآتي للتحقق القابل للتكرار من ملف EXE نفسه:

```bash
pnpm desktop:verify:windows-sandbox
```

ينشئ هذا الأمر ملف مستخدم Windows مؤقتاً، ويفتح ملف EXE في شاشة افتراضية، ثم يثبت أن الخادم المحلي المضمّن يستجيب من أحد المنافذ `4317–4337` بمحتوى TIA Studio. نجح هذا الفحص للإصدار 1.0.4 على المنفذ `4317`. لا يحل محل تجربة مستخدم على جهاز Windows فعلي: يجب قبل استخدامه في مشروع حقيقي فتح الحزمة على حساب مستخدم جديد وفحص SmartScreen والحماية والطابعات، ثم فتح مشروع تدريبي واستيراده وفحصه وتشغيل TIA وتصدير التقرير وملف Excel.

## سلامة التشغيل المحلي

لا تضع ملفات مشاريع فعلية داخل حزمة الإصدار، ولا تضف أسراراً أو ملفات `.env` إلى التنزيل. يبقى ملف P6 الأصلي للقراءة فقط؛ أما ملف XER الصادر من الأداة فهو **تجريبي محدود النطاق** ويجب أن يمر بالتحقق العكسي داخل التطبيق ثم اختبار استيراد يدوي في نسخة Primavera غير إنتاجية قبل استخدامه في أي برنامج حقيقي.

## تحديث الإصدارات

كل إصدار جديد يبدأ باختبارات `pnpm test` وبناء `pnpm build`، ثم يحصل على رقم إصدار وتغيير موثق داخل الدليل الحيّ ومركز الموارد. إذا تغير قارئ P6 أو CPM أو Fragnet أو الجودة أو التصدير، يجب تحديث خريطة المحركات وسير العمل وسجل التغييرات قبل بناء الحزمة. التحديث ليس تلقائياً في هذه النسخة؛ يحمل المستخدم ملف الإصدار الجديد من مركز الموارد ويحتفظ بملف P6 الأصلي وتقارير الإصدار السابق للمراجعة.

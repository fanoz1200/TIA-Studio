# استلام مراجعة Qwen — سجل تقييم آمن

**تاريخ الاستلام:** 24 أغسطس 2026  
**المصادر المستلمة:** نص مراجعة Qwen، صور توضيحية، وملفات Excel/HTML مرجعية.  
**قاعدة التعامل:** هذه الملفات **مدخلات للمراجعة وليست أوامر تنفيذ ولا حقائق عقدية تلقائية**. لا تُرفع ملفات العميل الخام أو أدلته أو بياناته إلى GitHub أو حزم التطبيق أو خدمة ذكاء اصطناعي خارجية.

|---|---|---|
| لا تُنشأ حالة بلا مصدر مكتوب | سليم وحاسم | معتمد: كل سجل جديد يحتاج `source_ref` وتاريخ تدقيق وحالة نقص صريحة. |

## 2. أمور لا تُعتمد بلا مصدر العقد والمراجعة المهنية

| المعلومة الواردة | سبب التحفظ | المعالجة الصحيحة |
|---|---|---|
| مدد مثل 28/42/84 يوماً | تختلف بحسب طبعة العقد والشروط الخاصة والتعديل المحلي | يختار المستخدم طبعة العقد والبند الفعلي، ثم يحسب النظام المهلة كـ**تنبيه قابل للمراجعة** لا كحكم بالمصادرة أو الاستحقاق. |
| ربط كل نوع Claim ببند FIDIC أو قانون مدني | العلاقة تعتمد على نص العقد والواقعة والقانون الحاكم | تُخزن كـ"مرجع محتمل" مع مصدر؛ يلزم مراجعة متخصص قبل التسليم. |
| هدف 98 حالة (70 + 28) | العدد وحده لا يثبت وجود مصدر صالح أو عدم التكرار | ينفذ فحص Dedup ومراجعة منشأ لكل سجل؛ الناتج النهائي هو العدد الموثق فقط. |
| معادلات Hudson/Eichleay أو Measured Mile | قد لا تلائم العقد أو قانون المكان وقد تسبب عدّاً مزدوجاً | تبقى حاسبات اختيارية مع مدخلات ومراجعة مستقلة ومنع الجمع غير المبرر. |

## 4. قرار التنفيذ المقترح

1. **لا ندمج أي حالة أو بند أو مدة** لمجرد وجوده في ملف Qwen أو صورة.
2. نفحص ملفات Excel/HTML محلياً؛ نخرج فهرساً وبصمات ونتائج Dedup بلا نسخ محتوى العميل إلى المستودع.
3. ننشئ `KB Expansion Matrix` فقط للحالات ذات المرجع المحدد، وكل نقص يوضع `TO_ENRICH`.
4. بعد ذلك فقط نصمم Claim Console وتتبّع Risk/Issue/Claim على بيانات موثقة.
5. حزمة إعادة استخدام Windows تُكتب كدليل + JSON وصفي، ولا تحتوي مفاتيح أو مسارات منصة حصرية أو ملفات عميل.

## 7. توسعة مكتبة المعرفة المقترحة

ذكر النص احتمال وجود حالات إضافية في ملف DOCX مرجعي، مع اقتراح الانتقال من 70 إلى 98 سجلاً بعد إزالة التكرار. لم يرد هذا الملف في مجموعة المرفقات الحالية، ولذلك **لم تُنشأ الحالات D-056 وما بعدها**. قبل أي توسعة، يلزم وجود المصدر الأصلي القابل للمراجعة، وتسجيل `source_ref` لكل حالة، وتنفيذ كشف تكرار حتمي، ووضع الحقول الغائبة كـ`TO_ENRICH` بدلاً من ملئها بالقياس أو التخمين.

## 8. مواصفة Claim Report Studio المقترحة

مقترحات المواصفة تستهدف غلافاً، فهرساً، سجل مراجعات، بصمة بيانات، أقسام Notice وSchedule Audit وTIA وWindows/Concurrency وDisruption وQuantum وسجل الأدلة والملاحق. تتوافق معظمها مع بنية Full Claim V1، لكن حالة التنفيذ تبقى كما يلي:

| الجزء المقترح | الحالة في TIA Studio | شرط التنفيذ أو التوسعة |
|---|---|---|
| Word ثابت + Fact Pack + غلاف/فهرس/سجل أدلة | منفذ في Full Claim V1 | مراجعة القالب من مختص قبل الاستخدام الخارجي. |
| HTML طوارئ وPDF اطلاع | غير منفذان كمسار Full Claim مستقل | يقيّمان بعد فحص شكل Word على ملفات غير حساسة. |
| Revision history وبصمة التطبيق/البيانات | جزئي | يُربط ببيان الإصدار وبصمة Fact Pack، لا بالملفات الخام. |
| Notice deadlines | هيكل بيانات وإشعارات موجودان | لا توجد قاعدة 28/42/84 عامة؛ يهيئها المستخدم وفق عقده. |
| DCMA/Logic/Progress audit | بوابة جودة وفحوص محلية موجودة | لا يدّعي تكافؤ P6 أو قبول أي معيار تعاقدي تلقائياً. |
| Concurrency/Measured Mile/Hudson/Eichleay | غير مطبقة كمحركات Claim نهائية | تحتاج بيانات كمية، افتراضات معلنة، وحماية من ازدواج العد، ومراجعة مهنية. |
| Legal matrix وسوابق وتحليل اعتراضات | معرفة مرجعية فقط | لا تتحول إلى رأي قانوني أو استحقاق آلي. |

## 9. Claim Console وNarrative Pack

المقترح الجيد هو جعل الحدث يمر عبر: **تصنيف موثق → أساس عقدي محتمل → دليل → Notice → تحليل زمني → تقرير**. ينفذ ذلك كـ"مساعد إعداد" لا كحكم استحقاق. ويمكن إضافة Narrative Pack لاحقاً كملفات منظمة وصور وجداول مجهّلة، بشرط أن يعيد المستخدم النص إلى مواضع محددة في القالب ولا يسمح للنموذج الخارجي بإعادة كتابة تقرير أو اختراع وقائع.

## 10. ما يمكن طلبه من Qwen إذا كان المصدر متاحاً

بدلاً من طلب كتابة كود أو تقرير قانوني، يفيد طلب واحد محدد: **فهرس مصدر للـ28 حالة الإضافية** يتضمن المعرف المقترح والعنوان واسم الملف/الفصل/الصفحة والنص الحرفي للمصدر وترخيص استخدامه وأي حقول ناقصة. هذه مادة تدقيق فقط؛ لا نحتاج، ولا نقبل، بيانات مشروع أو أسماء أطراف أو مراسلات حقيقية.

> **تحذير مهني:** TIA Studio أداة تحضير وتحليل وتوثيق. لا تثبت استحقاقاً ولا تحدد حقوقاً أو مواعيد تعاقدية نهائية. يجب مراجعة العقد والشروط الخاصة والوقائع بواسطة مختص مؤهل قبل أي إشعار أو مطالبة أو إرسال خارجي.

# قرار تنفيذ Claim Console بعد مراجعة Qwen

**الحالة:** قرار منتج وتنفيذ مرحلي، 24 أغسطس 2026.  
**القاعدة:** TIA Studio أداة تحضير وتحليل وتوثيق؛ لا تحدد الاستحقاق أو سقوط الحق أو التفسير القانوني النهائي. مراجعة العقد والشروط الخاصة والوقائع بواسطة مختص عقود/قانون لازمة قبل إرسال أي Notice أو Claim.

## 1. النتيجة المختصرة

مقترح Qwen في جوهره جيد: تحويل المسار إلى **Risk → Issue → Claim → Notice → TIA/Report** يجعل العمل قابلاً للتتبع ويمنع قفز المستخدم مباشرة إلى تقرير بلا أدلة. لكن لا يجوز أن يتحول هذا المسار إلى قاعدة تقول إن كل حدث يمنح وقتاً أو مالاً، أو أن مهلة `28/42/84` يوماً تسري تلقائياً.

> يبدأ Claim Console كـ **مساعد إعداد منضبط**: يجمع الوقائع والمصادر والنواقص والتنبيهات. ولا يصدر حكماً قانونياً أو حساب تكلفة/تعويض تلقائياً.

## 2. ما هو منفذ بالفعل ويمكن البناء عليه

| المجال | الموجود في TIA Studio | استعماله في Claim Console |
|---|---|---|
| التحليل الزمني | CPM/TIA/Fragnet محلي وفحوص جودة | ربط Issue بالأنشطة والأثر المحسوب مع وسم حدود المحرك ومراجعة P6 المطلوبة. |
| الأدلة والإشعارات | سجل أدلة، Notice محلي، ومسار Claim | جعل الدليل والإشعار متطلبين ظاهرين قبل السماح باكتمال بطاقة Claim. |
| التقرير | Full Claim V1 وFact Pack وWord قابل للتحرير | توليد مسودة منظمة من حقائق موثقة فقط وإظهار النقص صراحة. |
| الفريق | دعوات وأدوار ووصول منتهي المدة | تقييد المراجعة الداخلية؛ لا يمثل توقيعاً أو اعتماداً تعاقدياً. |
| الاستمرارية | GitHub وحزمة استلام يدوية وSetup/Portable | تسليم قابل لإعادة البناء ولا يعتمد على نموذج ذكاء خارجي واحد. |

## 3. نطاق Claim Console MVP المقترح

### 3.1 بطاقة المشروع والعقد — بيانات يملؤها المستخدم

لا بد من إدخال: طبعة العقد، نسخة الشروط الخاصة، القانون الحاكم، بند المطالبة الفعلي، وصف طريقة احتساب المدة، ونقطة بداية المهلة. إذا غابت هذه المعلومات، يعرض النظام `MISSING_CONTRACT_BASIS` ولا يخمنها.

### 3.2 خط سير قابل للتتبع

1. **Risk**: تنبيه أو خطر مبكر، بلا إعلان استحقاق.
2. **Issue**: واقعة بتاريخ ومصدر أولي ومسؤولية مدعاة وحالة دليل.
3. **Claim candidate**: ربط محتمل ببند عقدي يختاره المستخدم ويؤكد مصدره.
4. **Notice tracker**: تاريخ ومرجع ومعادلة مهلة *مُعدة من المستخدم*، مع تنبيه مراجعة لا حكم بمصادرة الحق.
5. **Schedule impact**: ربط اختيارى بتحليل TIA/Fragnet وبالأثر الزمني الفعلي وقيود التحقق.
6. **Full Claim draft**: Fact Pack + Word ثابت، مع سجل فجوات وموافقات داخلية.

### 3.3 حالات البيانات التي تمنع التضليل

| الحالة | معناها | سلوك النظام |
|---|---|---|
| `SOURCED` | يوجد مرجع محدد قابل للمراجعة | يسمح بالانتقال للخطوة التالية مع سجل مرجع. |
| `TO_ENRICH` | المحتوى أو الدليل ناقص | يظهر في التقرير ولا يسمح بوصفه كحقيقة نهائية. |
| `REVIEW_REQUIRED` | يلزم تدقيق عقدي/فني | يبقى في قائمة المراجعة ولا يولد نتيجة تلقائية. |
| `REJECTED` | تكرار أو مصدر غير صالح | لا يدخل Full Claim. |

## 4. ما لا ننفذه الآن ولماذا

| البند | السبب | شرط البدء لاحقاً |
|---|---|---|
| قاعدة ثابتة 28/42/84 يوماً | تختلف باختلاف طبعة العقد والشروط الخاصة | ملف Contract Profile موثق ومراجعة مختص. |
| محركات Hudson/Eichleay/Measured Mile | تحتاج مدخلات كمية ومنع ازدواج وتعريف عقدي | عقد بيانات وتحقق مستقل لكل طريقة. |
| تصنيف آلي للاستحقاق T/C/M | الواقعة والعقد والقانون تحدد النتيجة | يقتصر الآن على قائمة اختيار ومصدر محتمل يراجعه المستخدم. |
| توسعة الحالات إلى 98 | لا يوجد بعد مصدر موثق للـ28 حالة المقترحة | فهرس مصدر وترخيص وكشف تكرار. |
| إدخال ملفات Excel/HTML المرفقة مباشرة | قد تكون قوالب أو مشتقات أو تتضمن بيانات حساسة | Mapping محلي بعد مراجعة منشأ كل سجل. |

## 5. ترتيب التنفيذ الذي أوصي به

1. بناء **Contract Profile + Risk/Issue/Claim Register** محلياً مع حالات البيانات أعلاه.
2. بناء Deadline Tracker قابل للتهيئة من المستخدم، لا بأرقام FIDIC مفترضة.
3. ربط السجل بـNotice وFact Pack وFull Claim V1.
4. بناء `KB Expansion Matrix` للحالات ذات مصدر وترخيص فقط.
5. بعد عينة مموهة ومراجعة مختص: تحسين Narrative Pack والتنسيق، ثم تقييم حاسبات Disruption/Quantum كل واحدة على حدة.

## 6. ما يفيد طلبه من Qwen الآن

لا نطلب منه كتابة كود أو تقرير قانوني أو تحليل لملف عميل. نطلب فقط **فهرس مصدر** للـ28 حالة المقترحة بصيغة ملف JSON/CSV، باستخدام الطلب المحفوظ في:

`agent-kits/QWEN_SOURCE_INDEX_REQUEST_AR.md`

الفهرس المقبول يحتوي مرجعاً ببليوغرافياً أو رابطاً عاماً، وملخصاً قصيراً بصياغة أصلية، وترخيص/حالة استخدام، وحالة نقص. لا يُقبل نص منسوخ مطول، ولا أي أسماء مشاريع أو أطراف أو مراسلات أو بيانات مالية حقيقية.

## 7. معيار الجاهزية للبدء في Claim Console

يبدأ التنفيذ البرمجي فور اعتماد هذا النطاق. لا يحتاج انتظار Qwen لبناء سجل Risk/Issue/Claim الأساسي. لكن **توسيع مكتبة المعرفة أو جعل مرجع عقدي تلقائي** ينتظر فهرس المصدر والمراجعة المهنية.

# مراجعة أولية لأدوات XER المفتوحة المصدر

> **الغرض:** هذه مذكرة فنية أولية لدعم محرك TIA المحلي. ليست رأياً قانونياً ولا تمنح استحقاقاً تعاقدياً. لا يُنقل أي كود أو يُضمّن أي مكوّن قبل مراجعة ترخيصه واختباره على ملفات P6 غير حساسة.

## النتيجة التنفيذية

يحتوي TIA Studio بالفعل على قارئ XER وPMXML محلي ومحرك CPM/Fragnet حتمي. لذلك فإن الدور المفيد للأدوات الخارجية في هذه المرحلة هو **التحقق المتبادل، وبناء حالات اختبار، وتحسين كشف بنية ملف XER**؛ وليس استبدال محرك التحليل أو فتح ملف المستخدم خارج حدود التطبيق. لا يوجد قرار إدماج تلقائي من هذه المراجعة.

| الأداة | ما تؤكده المصادر | الترخيص المعلن | القرار المبدئي في TIA Studio |
|---|---|---|---|
| PyP6Xer | قارئ Python لـXER يعرض الأنشطة وWBS والعلاقات والموارد والتقويم، ويدّعي دعم الكتابة وتحليلات أولية. | LGPL-2.1 | **مرجع تحقق خارجي فقط** في بيئة التطوير؛ لا يُضمّن في تطبيق Electron أو خادم الإنتاج حالياً. [1] |
| xerparser | قارئ Python يهيكل جداول XER ويتحقق من غياب الجداول والعلاقات المرجعية، ومختبر لإصدارات P6 15.2–19.12 بحسب المستودع. | GPL-3.0 | **لا نقل أو تضمين للكود** في المشروع؛ يمكن الرجوع إلى قواعد التحقق المعلنة كمصدر اختبار مستقل مع صياغة تحققنا الأصلية. [2] |
| xer-reader | قارئ Python يقدّم قائمة الجداول وفحص الجداول/المراجع اليتيمة وتصديراً إلى CSV وJSON وExcel. | GPL-3.0 | **لا نقل أو تضمين للكود**؛ يستفاد منه فقط كمرجع لسلوك اختبار ملفات XER في بيئة منفصلة. [3] |
| PrimeveraXEREditor | تطبيق Java تجريبي يستخدم MPXJ؛ يوضح مسار تصميم منفصل لقراءة وتحليل XER. | ترخيص التطبيق غير ظاهر في الصفحة المقروءة | **مرجع تصميم فقط**؛ لا نقل أو تضمين للكود. [4] |
| MPXJ | مكتبة Java متعددة المنصات تدعم قراءة PMXML وXER وكتابة XER، وتتعامل مع ملفات جداول أخرى متعددة. | LGPL-2.1 | **مرشح تحقق لاحق فقط** عبر عملية منفصلة اختيارية؛ لا يدخل الآن ضمن حزمة Electron أو خادم الإنتاج. [5] [6] |
| PyP6 | أدوات Python تعتمد على قاعدة SQLite الخاصة بـP6 لتحميل OBS/WBS/الأنشطة والعلاقات من CSV. | MIT | **لا دمج ولا تشغيل على قاعدة مستخدم**؛ تصلح فقط كفكرة لخط أنابيب CSV اختياري بعد نسخ احتياطي وموافقة صريحة، لأن أي خطأ في الكتابة يؤثر في قاعدة P6 مباشرة. [7] |
| ProjectLibre Desktop | بديل مفتوح المصدر لتخطيط المشاريع مع مخطط Gantt وPERT، لكنه يُسوَّق بديلاً لـMicrosoft Project لا كقارئ XER موثق. | يلزم التحقق من ترخيص الإصدار المحدد قبل أي اعتماد | **رابط مرجعي للمستخدم فقط**؛ لا يُعرض كبديل متوافق مع P6 أو كجزء من محرك TIA. [8] |

## ما يمكن إضافته بأمان

التحسين المقترح هو إضافة **طبقة تحقق مقارن** إلى اختبارات التطوير: ملفات XER مُجهّلة وغير حساسة تُقرأ بمحرك TIA الحالي، ثم تُقارن جداولها الأساسية فقط — `PROJECT` و`PROJWBS` و`TASK` و`TASKPRED` و`CALENDAR` — مع ناتج قارئ خارجي مستقل. تُسجّل الفروقات بوصفها تنبيهات اختبار، ولا تُغيّر جدول المستخدم ولا تصدر ملف XER جديداً تلقائياً. يظل التصدير التجريبي مصحوباً بالتحقق العكسي الموجود في المنصة.

ينبغي أيضاً تقوية بوابة الجودة الحالية بقواعد أصلية واضحة: وجود الجداول الأساسية، اكتمال الربط المرجعي بين الأنشطة والعلاقات وWBS، تمييز التقويم غير الموجود، والإبلاغ عن ترميز الملف بدل تخمينه. هذه قواعد مأخوذة كفكرة تحقق قابلة للمراجعة من السلوك الموصوف للأدوات الخارجية، لا كنقل للكود.[2] [3]

تؤكد وثائق Oracle أن استيراد P6 XML/XER يتضمن خيارات منفصلة للمشروع والـBaseline والـScenario، وقرارات مطابقة/تعارض للكائنات، وسجل استيراد للمراجعة اللاحقة. لذلك يبقى مبدأ TIA Studio هو **القراءة والتحليل أولاً، ثم إخراج تجريبي مع تحقق عكسي**؛ ولا يتحول أي تحليل إلى تعديل لملف أو قاعدة P6 الأصلية.[9]

## ما لا يُدمج الآن

لا يعتمد التطبيق على حزم Python أو Java خارجية في نسخة سطح المكتب؛ فهذا يضيف وقت تشغيل وامتدادات وترخيصاً جديداً إلى منتج Windows/Linux ذي الملف الواحد. كما أن أدوات GPL لا تُنسخ ولا تُربط مع التطبيق الحالي. أما MPXJ فيحتاج، حتى مع ترخيص LGPL-2.1، مراجعة حزمة التوزيع وتراخيص تبعياته وخيار استدعائه قبل أن يصبح جزءاً من منتج سطح المكتب. لا تُرسل ملفات P6 أو بيانات المشروع إلى GitHub أو خدمة خارجية خلال هذا التقييم.[5]

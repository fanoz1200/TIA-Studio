# مراجع أولية لمنهج Window Analysis

> هذا الملف مرجع تعليمي وتقني لا استشارة قانونية ولا إثبات استحقاق أو EOT في مشروع معين. اختيار المنهج وتقييم السجلات والسببية والتزامن يظل عملاً مهنياً ومقيداً بالعقد والقانون والوقائع.

## التعريف التشغيلي المقترح في TIA Studio

**Window Analysis / Time Slice** هو تحليل رجعي يقسم مدة التنفيذ إلى نوافذ زمنية متتابعة (مثل أسابيع أو شهر أو بين تاريخَي تحديثين)، ثم يقارن داخل كل نافذة حالة البرنامج المعاصرة، والتقدم، والمسار الحرج أو الأطول، والوقائع والأدلة المرتبطة بها. لا يساوي ذلك إدخال كل الوقائع في Fragnet واحد وتشغيل TIA مجمع.

## ما هو موجود حالياً قبل التطوير

يوجد محرك `runWindowTIA` محلي. هو يجمع الوقائع الواقعة في `AnalysisWindow` ثم يضيف الـFragnets بالتتابع إلى نسخة CPM متراكمة ويسجل أثراً تراكمياً. السرد الحالي يسمي هذا صراحة **«تحليل TIA مجمّع داخل نافذة زمنية»**. لذلك فهو مفيد كـ**Modeled / additive windowed TIA**، لكنه ليس محرك **Time Slice Windows** رجعي كامل يعتمد على مقارنة نسخ Updates متتابعة وتقدم فعلي داخل كل نافذة.

## متطلبات مسار Time Slice Windows حقيقي

1. حفظ لقطة برنامج عند بداية ونهاية كل نافذة، مع اسم الملف، نوعه، Data Date، وسجل نشاط/علاقات/تقويم قابل للمراجعة.
2. تحديد حدود النافذة ومبررها قبل الحساب، وعدم تعديل النسخ الأصلية.
3. فحص توافق اللقطات: المشروع، التواريخ، التقويم، منطق العلاقات، القيود المدعومة، وعدد الأنشطة والتغييرات الجوهرية.
4. عرض تغير تاريخ الإكمال والمسار الحرج/الأطول بين اللقطتين بوصفه **فرقاً ملاحظاً** لا نسبته تلقائياً إلى طرف.
5. ربط كل واقعة وأدلتها وسجلها الزمني بالنافذة؛ التزامن «مرشح للمراجعة» وليس تخصيص استحقاق.
6. فصل جدول نتائج Time Slice الرصدي عن نتائج الـFragnets المُنمذجة، ثم توثيق التحفظات للتصدير.

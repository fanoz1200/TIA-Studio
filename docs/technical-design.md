# التصميم الفني — TIA Studio 1.0

## الغرض

TIA Studio أداة مستقلة تعمل داخل المتصفح لتحليل الأثر الزمني للأحداث وفق منهج **Time Impact Analysis**. تستخدم الأداة نسخة من البرنامج الزمني المختار سابقاً للحدث، وتضيف شبكات تأخير مستقلة (Fragnets) بروابط منطقية صريحة، ثم تعيد حساب شبكة CPM وتقارن تاريخ الإكمال قبل الإدراج وبعده. النتيجة هي قياس أثر زمني فني، وليست حكماً قانونياً على الاستحقاق أو التعويض.

## نموذج البيانات

| الكيان | الحقول الجوهرية | الدور |
|---|---|---|
| ProjectSchedule | الاسم، تاريخ البدء، التقويم، الأنشطة، العلاقات | نسخة تحديث البرنامج المختارة للتحليل |
| Activity | المعرف، الاسم، المدة، WBS، المالك، نوع الحالة | عقدة CPM، وتقبل المدة صفر للـ milestones |
| Relationship | predecessorId، successorId، type، lag | منطق FS/SS/FF/SF والـ lag بالأيام |
| Fragnet | معرف الحدث، الوصف، السبب، تاريخ الحدوث، قائمة الأنشطة والعلاقات | شبكة الأنشطة التي تمثل أثر حدث التأخير |
| TIAResult | الإكمال قبل/بعد، فرق الأيام، المسار الحرج، العائمة، فحص الجودة | سجل فني قابل للتصدير والتدقيق |

## خوارزمية CPM

يفحص المحرك معرفات الأنشطة، العلاقات المكررة، المدد السالبة، والحلقات المنطقية. ثم ينشئ ترتيباً طوبولوجياً للشبكة. يمثل الزمن بعدد أيام تقويمية نسبية من تاريخ بدء المشروع، ما يجعل نتيجة فرق الأيام متسقة حتى عند عدم إدخال تاريخ تقويمي.

في التمرير الأمامي، تحسب بداية النشاط من أقصى القيود الواردة: `FS: EFp + lag`، و`SS: ESp + lag`، و`FF: EFp + lag - duration`، و`SF: ESp + lag - duration`. ثم يكون `EF = ES + duration`. يساوي إكمال المشروع أكبر نهاية مبكرة لجميع الأنشطة.

في التمرير الخلفي، تبدأ الأنشطة الطرفية عند تاريخ إكمال المشروع، ثم تحسب أقصى بداية متأخرة مسموحة من الأنشطة اللاحقة. تعرّف العائمة الكلية بالمعادلة `TF = LS - ES`. يعد النشاط حرجاً عندما تكون عائمته ضمن هامش عددي صغير من الصفر.

## خوارزمية Time Impact Analysis

| الخطوة | عملية الأداة | دليل المراجعة |
|---|---|---|
| 1 | حفظ نسخة غير قابلة للتعديل من تحديث البرنامج المختار | اسم النسخة وتاريخ البيانات |
| 2 | حساب CPM قبل الحدث وتسجيل الإكمال والمسار الحرج | جدول baseline CPM |
| 3 | إدراج أنشطة الـ fragnet وعلاقاتها وروابطها مع شبكة الأساس | سجل النشاط والعلاقة المنشأة |
| 4 | فحص الشبكة المركبة ثم إعادة حساب CPM | قائمة جودة الشبكة |
| 5 | مقارنة الإكمال المتوقع قبل وبعد الإدراج | فرق الأيام وتواريخ الإكمال |
| 6 | توضيح العائمة والمسار الحرج بعد الإدراج | الأنشطة الحرجة والـ float المفقود |
| 7 | إصدار تقرير قابل للطباعة/الحفظ متضمناً الافتراضات والتنبيه المنهجي | تقرير TIA |

الأثر الزمني: `Impact Days = Impacted Completion − Baseline Completion`. إن كان الفرق صفراً، تسجل الأداة أن الحدث استهلك عائمة أو لم يصل إلى الإكمال المخطط. لا تصدر الأداة قراراً تلقائياً بشأن قابلية التعويض؛ فهي تعرض فقط تصنيف المستخدم والوقائع الزمنية وتحذر عند وجود أحداث متزامنة ظاهرة.

## حدود الإصدار الأول

يدعم الإصدار الأول شبكات CPM بدون حلقات، العلاقات FS/SS/FF/SF، lags موجبة أو سالبة، المدد بالأيام التقويمية، ملفات CSV وJSON، الإنشاء اليدوي، وإدراج Fragnet واحد لكل تحليل مع سجل أحداث متعدد. لا يدّعي استيراد ملف XER الأصلي، ولا يستبدل مراجعة خبير برنامج أو بنود العقد أو تحليل التزامن التفصيلي. لملفات P6 وMS Project، تصدّر الأنشطة والعلاقات كـ CSV ثم تُستورد في التطبيق.

## جودة التحليل

يوقف المحرك التحليل عند حلقة منطقية أو علاقة تشير إلى نشاط مفقود. ويرفع تحذيراً، من دون إيقاف، عند: غياب الأنشطة الحرجة الظاهرة، وجود نشاط بلا روابط، تاريخ حدث سابق على تاريخ بدء النسخة، أو Fragnet بلا رابط دخول أو خروج. يظل التقرير صريحاً في أن قوة النتيجة تعتمد على صحة التحديث المعتمد وحالة الأنشطة عند تاريخ الحدث.

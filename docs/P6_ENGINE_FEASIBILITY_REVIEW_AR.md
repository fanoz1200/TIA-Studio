# مراجعة جدوى محرك P6/XER خفيف داخل TIA Studio

**تاريخ البدء:** 23 أغسطس 2026  
**الحالة:** تقييم تقني وترخيصي فقط. لا توجد مكتبة خارجية مدمجة في التطبيق، ولا تُرسل ملفات المستخدم إلى أي خدمة.

## ما تم التحقق منه حتى الآن

تبيّن من وثائق MPXJ الرسمية أن المكتبة تقرأ وتعالج وتكتب بيانات المشاريع من Java و.NET وPython وRuby، وتذكر صراحة دعم Primavera P6 بصيغ PMXML وXER وقاعدة البيانات. كما تذكر قراءة بيانات من P6 Web Services وP6 EPPM وOracle Primavera Cloud. إصدار صفحة المشروع المنشور عند المراجعة هو 16.7.0، مع Java 1.8 كحد أدنى في معلومات البناء. [1]

> وجود دعم صيغة في مكتبة لا يساوي تلقائياً تطابقاً حسابياً أو تشغيلياً كاملاً مع Primavera P6 Professional. لذلك لن تعرض TIA Studio أي نتيجة على أنها «نتيجة Primavera» إلا بعد مجموعة مقارنة واستيراد عكسي محددة ومثبتة.

| المسار | الفائدة المحتملة | التكلفة/القيد | القرار الحالي |
|---|---|---|---|
| محرك TIA/CPM المحلي | يعمل بلا Java، وبالحساب الحتمي المملوك للتطبيق، ومناسب للـ Fragnet والتحقق الداخلي | يحتاج اختبار تطابق أقوى مع بيانات P6 الفعلية | يبقى المحرك الأساسي الآن |
| MPXJ كمدقق خارجي اختياري | قارئ/كاتب متعدد الصيغ مع دعم معلن لـ XER وPMXML | يحتاج Java runtime وحزمة منفصلة ومراجعة LGPL وحدود كتابة XER | مرشح **Verifier Sidecar** فقط، وليس مدمجاً الآن |
| P6 Integration API الرسمي | يتيح تكاملاً أقرب لبيئة P6 عند توافرها لدى المستخدم | Java SDK وترخيص/تنصيب Oracle وبيئة P6؛ ليس بديلاً مجانياً خفيفاً موزعاً مع TIA Studio | جسر اختياري مستقبلي، لا دمج تلقائي |
| التحرير/الكتابة المباشرة لقاعدة P6 | قد يبدو أقرب إلى P6 | خطر عالٍ على قاعدة المستخدم، والمسار غير مناسب لتحليل مطالبة قابل للمراجعة | مرفوض بالكامل |

## استنتاج مرحلي

المسار الواقعي للحصول على أرقام دقيقة ليس إدخال «نسخة Primavera» غير موثقة داخل الواجهة. المسار الأدق هو: قراءة XER أو PMXML محلياً، تنفيذ CPM/TIA/Fragnet حتمياً، إنشاء مخرجات تدقيق، ثم مقارنة اختيارية في بيئة مستخدم غير إنتاجية مع P6 أو مدقق مستقل قبل أي اعتماد أو رفع للاستشاري. لا بد أن يبقى ملف XER الأصلي للقراءة فقط، وأن يخضع أي XER مُصدّر للاستيراد العكسي اليدوي في نسخة تجريبية من P6.

لا يُشغّل المستودع الخارجي في هذه المرحلة، ولا يُنسخ كوده، ولا يُربط جسر تحكم مباشر إلى برنامج Primavera على جهاز المستخدم. سيتطلب ذلك لاحقاً تثبيتاً صريحاً من المستخدم لنسخة P6، ومساراً محلياً واضحاً، ومراجعة الترخيص، واختباراً على نسخة غير إنتاجية مع نسخة احتياطية مستقلة.

## نتيجة مراجعة API الرسمي

تفتح وثائق Oracle الرسمية دليل **P6 and P6 Professional Integration API Programming Guide for On-Premises Version 21**، ما يؤكد أن مسار API موجود بوصفه مسار تكامل رسمي منفصل عن XER وPMXML. لكن العرض النصي المتاح من صفحة الدليل يعتمد على واجهة مساعدة ديناميكية ولم يكشف عقد التشغيل أو التفويض الكامل في هذا الفحص. لذلك لا يُفترض أن هذا API متاح بلا ترخيص أو أنه قادر على التحكم في واجهة P6 المكتبية بالطريقة المطلوبة دون تثبيت محلي وتحقق عملي من بيئة المستخدم. [3]

القرار المؤقت هو عدم إنشاء «زر تحكم في Primavera» ولا موصل بيانات ولا عملية تلقائية. أي نموذج أولي لاحق يجب أن يعمل كأداة سطح مكتب محلية منفصلة، وأن يطلب من المستخدم اختيار ملف P6 أو مسار تصدير صريح، وأن يكون افتراضه الافتراضي القراءة فقط.

## قارئات Python: استخدام مرجعي فقط في هذه المرحلة

يظهر المستودع الأصلي لـ **PyP6Xer** أنه مكتبة Python لقراءة وتحليل XER، وأنه يحتوي كذلك على مسار كتابة. الترخيص الظاهر هو `LGPL-2.1-or-later`، وهو أخف من GPL لكنه لا يجعل دمجه تلقائياً آمناً: سيستلزم ذلك إضافة Python runtime إلى إصدار Windows/Linux، وتدقيقاً منفصلاً للتوزيع والإشعارات والاعتمادات، ثم اختبار قراءة وكتابة متقاطع. لذلك لا يُضم إلى تطبيق TIA Studio حالياً، ويمكن لاحقاً تشغيله في بيئة تطوير معزولة كـ«مدقق ثانٍ» على ملف اختبار لا على ملف المستخدم الحي. [4]

أما **xerparser** فهو قارئ Python يحول محتوى XER إلى كائنات Python، ويصرح بأنه اختُبر على ملفات مُصدّرة من P6 بين الإصدارات 15.2 و19.12، لكنه مرخص `GPL-3.0`. لذلك يُستبعد من الحزمة ومن أي ربط أو نسخ كود داخل منتج TIA Studio، ويمكن الاستفادة من ملاحظاته ووثائقه علناً كمادة مقارنة فقط. [5]

| الخيار | القراءة | الكتابة/التصدير | الترخيص الظاهر | قرار TIA Studio الآن |
|---|---|---|---|---|
| محرك TIA المحلي | XER وP6 XML بالقراءة المحلية | XER تجريبي مع تحقق عكسي | ملكية المشروع | المسار الأساسي |
| MPXJ | صيغ متعددة منها P6 | حسب الصيغة | LGPL | مدقق منفصل محتمل بعد مراجعة توزيع |
| PyP6Xer | XER | يتضمن مسار كتابة | LGPL-2.1-or-later | مرجع ومدقق تطوير محتمل، غير مدمج |
| xerparser | XER | قارئ | GPL-3.0 | مستبعد من التوزيع والدمج |
| Oracle Integration API | تكامل رسمي مشروط بالبيئة | يعتمد على P6 المحلي والامتيازات | رخصة Oracle | جسر محلي مستقبلي فقط بعد إثبات الترخيص |

## ما الذي يمكن لواجهات Oracle أن تفعله فعلاً

توضح Oracle أن **P6 Professional API** يحتاج إلى JDK، ونظام تشغيل مدعوم، وقاعدة بيانات P6 Professional مدعومة؛ ومن ثم فهو ليس مكتبة JavaScript خفيفة يمكن تضمينها داخل حزمة TIA Studio وتشغيلها على كل جهاز. [6] وتصف Oracle واجهات Integration API وP6 Professional Integration API بأنها واجهات Java متعددة المنصات. [7] لهذا السبب لا يمكن تحويل وجود API إلى وعد بأن التطبيق «يتحكم في Primavera» لدى كل مستخدم.

أما REST API فهو مسار P6 EPPM خادمي منفصل، ويحتوي توثيقه على المصادقة والتفويض وHTTPS وOAuth، وواجهات قراءة/تعديل لأنشطة، تقاويم، خطوط أساس، موارد، وتصدير، إضافة إلى طلبات جدولة وفحص جدول. [8] وهو خيار قابل للنقاش فقط لمؤسسة لديها بالفعل P6 EPPM، مسؤول نظام، حسابات وامتيازات، وموافقة مكتوبة على نطاق القراءة أو الكتابة. لا يُفعل من تطبيق TIA Studio افتراضياً، ولا تُطلب بيانات دخول أو عنوان خادم قبل اختيار المستخدم لمسار التكامل هذا صراحةً.

| المسار | ما يوفره فعلياً | ما لا يوفره وحده | متطلب البدء |
|---|---|---|---|
| XER/PMXML محلي داخل TIA Studio | قراءة محلية، نموذج CPM/Fragnet حتمي، تقارير وتصدير تجريبي | مطابقة كاملة لمحرك حساب P6 أو ضمان قبول كل إصدار | ملف اختباري من المستخدم والتحقق العكسي |
| Oracle P6 Professional API | تكامل Java محلي مع بيئة P6 Professional المدعومة | تشغيل بلا JDK أو قاعدة P6 أو تثبيت رسمي | حاسوب Windows/Linux مجهز وP6/قاعدة مرخصان |
| Oracle P6 EPPM REST | قراءة/تعديل وطلبات جدولة على خادم EPPM معتمد | التحكم في واجهة P6 المكتبية أو استخدام بلا حساب وموافقة | خادم EPPM متاح وOAuth/حساب أقل صلاحية |
| MPXJ / PyP6Xer | قارئ/مدقق ثانٍ محتمل منفصل | بديل رسمي عن حساب P6 أو ضمان تصدير قابل للقبول | مراجعة ترخيص وتوزيع وحزمة اختبار مرجعية |

## تقييم ProjectLibre وما يشبهه من برامج Gantt المكتبية

لا يحقق ProjectLibre الهدف المطلوب بوصفه «نسخة P6 خفيفة تُدمج داخل التطبيق». فالمستودع الظاهر هو مشروع Java Desktop كبير يتضمن طبقات `core` و`exchange` و`ui`، ويشير مسار قارئ XER فيه إلى قارئ MPXJ نفسه؛ لذلك لا يضيف محرك حساب P6 مستقلاً يمكن نقله إلى تطبيق Electron/TypeScript. [9] كما أن الإصدار المنشور الظاهر في صفحة المستودع أقدم من التغييرات المصدرية، ما يجعل الاعتماد عليه كمرجع نتائج دون حزمة اختبار مرجعية مخاطرة تشغيلية. [9]

وتذكر صفحة توزيع ProjectLibre ترخيص **CPAL 1.0**، وهو ترخيص يحتاج مراجعة امتثال مستقلة قبل أي تضمين أو إعادة توزيع، ولا يصلح افتراضياً لنسخ الكود أو تضمينه في حزمة TIA Studio. [10] لذلك يمكن للمستخدم، إن اختاره، استعماله كتطبيق منفصل للمشاهدة العامة فقط، لكنه ليس بديلاً موصى به لحسابات مطالبة تعاقدية أو لتوليد XER قابل لإعادة الاستيراد.

| البديل | الفائدة المحتملة | القرار الحالي |
|---|---|---|
| ProjectLibre | عارض/محرر Gantt عام منفصل وواجهة تقليدية | لا دمج ولا نسخ كود؛ ليس محرك P6 معتمداً |
| GanttProject | رسم جانت عام مفتوح؛ لا يثبت دعماً مكافئاً لـ XER/P6 | غير مناسب للمسار الحسابي أو التصدير |
| MPXJ | التحقق المتقاطع من بنية الملفات على عملية منفصلة | أفضل مرشح للـ verifier بعد مراجعة LGPL وحزمة اختبارات |
| محرك TIA المحلي | الحساب الحتمي ومراجعة Fragnet تحت اختبارنا المباشر | يظل المحرك الأساسي حالياً |

## مستخرج xer4PowerBI

مشروع `xer4PowerBI` هو دالة Power Query تستخرج جداول XER داخل Power BI أو Excel، ويطلب وجود Power BI أو Power Query في Excel. لا يقدم جدولة CPM أو إعادة حساب أو Fragnet أو تصدير XER. [11] كما أن مستودعه معلن بترخيص GPL‑3.0؛ ولذلك لا يجوز نسخه أو تضمينه في التطبيق. يمكن الاستفادة من فكرة عرضه للجداول كمرجع اختبار يدوي مستقل فقط، من دون تنفيذ كوده أو إرسال ملف المستخدم إليه.

## تدقيق أدق لـ MPXJ

تذكر وثائق MPXJ أنه يقرأ ويكتب P6 XER وPMXML، وأن لديه CPM schedulers تحسب ES/EF/LS/LF وتهدف إلى الاقتراب من نتائج أدوات الجدولة التي تستخدم CPM. [12] هذه قدرة مفيدة لمسار **تحقق متقاطع منفصل**: نقارن عدّ النشاط والعلاقات والتقاويم والمواعيد والـFloat على نسخة بيانات لا تغادر جهاز المستخدم. لكنها ليست تصريحاً بمطابقة Primavera في كل سيناريو؛ فالوثيقة نفسها تصف التقارب ولا تمنح ضماناً تعاقدياً مكافئاً لمحرك P6، كما أن قواعد longest path والتقاويم والقيود والـresource leveling قد تتباين بين المشاريع والإصدارات. [12]

لهذا يُصنَّف MPXJ كأفضل خيار مستقبلي محتمل لعملية verifier اختيارية معزولة، لا كمحرك يُضمَّن الآن داخل Electron ولا كبديل عن P6. يبدأ أي نموذج أولي فقط بعد: مراجعة LGPL والتوزيع الديناميكي، إنشاء حزمة XER/PMXML مجهّلة ومعتمدة للاختبار، ومقارنة تلقائية لا تسمح بإصدار ملف ادعائي إذا تجاوز الفرق حدوداً معلنة.
